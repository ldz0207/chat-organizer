# WorkBuddy：单独诊断，不自动 selfheal

原包声称某版本的空间显示依赖 cwd、任务标志、数据库和 JSONL sidecar 一致性；它未提供可确认适用范围的发行版本。**这些是历史实现线索，不是所有版本的公开合同。** 本包不附带旧写库脚本，也不承诺已修复任何真实应用。

当用户报告空白历史/空间异常：
1. 记录准确应用版本、设备、发生时间、最近操作和症状；先在官方 UI/帮助/支持渠道核对已知问题
2. 只读确认会话是否仍可从原生历史、搜索、归档入口打开。缺少本地文件不等于丢失，可能是云端或权限问题。不得自动将 cwd 当唯一真相
3. 受支持导出可用时保留恢复副本；无法一致备份就停止写入。多份记录冲突不能按“最大文件”选真本，压平路径编码不能反推出唯一原路径
4. 有官方受支持修复入口时列出具体对象、字段/文件影响、风险、备份、撤销与验证方案，**另获修复批准**。分组批准不包含修复
5. 无受支持修复方法：保持只读，给用户诊断摘要和官方支持/手动恢复建议；不自动补档、改库、改 JSONL，不后台重试

若用户另外明确要求研究旧脚本/离线修复：这是独立任务，仅在授权副本研究；核对当前 schema、路径编码、数据完整性、活动状态、所有副本与附件。未知版本、编码样本不足/冲突、非法 JSONL、无法可靠恢复任一项都阻止修复写入。真实修复需另行审核和批准，本包未实现。

继承的教训：迁移路径可能影响历史定位；字符串替换可破坏 JSON 转义；合法 JSON 不等于语义完整；“只增不删”仍可能覆盖原内容。任何新修复工具应结构化解析、写前/写后全量校验、确保备份成功、处理异常退出和并发，绝不能只凭计数为零判定健康。
