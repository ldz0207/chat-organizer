# 按实际内容命名与本批结束后补命名

## 范围与授权

用于用户明确要求按对话实际内容重命名已有会话，或在本批正在运行的会话结束后补命名。先核对当前应用、版本、设备、账户/工作区与原生读取/改名/读回能力，记录用户请求和固定会话 ID 集合。若用户要求先确认方案，先给原标题 → 拟议标题；已经明确授权本批改名则直接完成范围内工作，不重复请求批准。分组更新的确认要求与标题授权分别处理。

保留现有分组、置顶、排序设置、项目关联、工作目录、运行状态和历史。默认受保护的项目会话或已有手动标题，只有用户明确将其纳入本批改名范围时才处理；手动锁需明确解除。不扩大到未来新建会话、其他应用、账户或设备，不因跟进任务自动产生持续管理权。队列及原标题属于私人运行记录，只保存在用户控制位置，不随技能发布到公共仓库。

## 阅读实际内容与拟名

通过原生接口阅读用户请求、关键交付及后续主题变化。标题和列表摘要只用于找对象，不能作为内容判读的替代。必要时分页补读：最新轮次不足以解释主要工作时，补读相关早期轮次；发现后续业务转向时调整依据。记录覆盖范围与少量证据轮次 ID，不默认保存整段聊天或附件。

按主要工作与最终实际交付命名，用简短动作加核心对象，通常在20至35字以内，也可更短；用户指定风格时沿用。多主题只有两项都实质重要时才并列，不能把一句题外话变成主题。准确的原标题保留。例：“测试”后实际完成资料归档 → “整理资料归档与索引”；浏览器连接检查后主要交付笔记备份 → “备份云端笔记并修复浏览器连接”。示例不绑定产品或设备。

不加日期、emoji、分组前缀或无助于辨识的套话；不把生日、住址、证件、私密家庭身份等信息从内容带到侧边栏。普通命名不必打开全部附件；确实依赖附件事实但无法读取时保留原名并记录证据不足，不猜测。

## 运行结束后队列

本批初始盘点中已运行、或执行期间转为运行的授权会话，登记为 `pending`，保留原值及 `expectedOriginalTitle`。只添加本批原始清单内的会话，不能每次检查重新把所有新会话纳入。每次跟进重新读取真实状态和最新内容；旧建议不等于最终标题。

普通目标必须符合当前宿主已核实的空闲/未加载状态，并且无未结束的业务轮次。活动、状态未知、查询失败或源内容不够时继续等待或记录待核对；不停止、恢复、归档会话，不向其他聊天发送消息，也不重做业务工作。业务完成但后续又启动新业务时重新等待。

当前聊天可采用一个有限例外：记录原用户命名工作轮次 `anchorUserWorkTurnId`，原生读回该轮次已经完成；当前活动仅是本次专用标题收尾维护，且没有后来启动的非维护业务时，可在维护收尾命名本聊天。缺少锚点完成证据、存在新业务或不能区分维护回合时继续等待。此例外只适用于已结束的原用户工作，不适用于其他活动业务会话。

用户明确要求结束后跟进已授权本批有限等待。用宿主受支持的真实结束事件或原生跟进自动化；没有唤醒机制时只能在后续实际调用时检查，明确限制，不声称后台运行。专用跟进固定队列、常规等待安静，全部条目终结后暂停并读回跟进状态；不删除或归档聊天。只有需要用户处理的实际异常或本批完成才通知，通知频率服从用户要求。

## 写前、写入与读回

逐项串行执行，先保存原标题、内容依据、原生会话 ID、预期版本/状态和写入检查点。写前重新原生读取标题、状态、最新业务轮次和可用 revision；当前标题不等于 `expectedOriginalTitle` 时标记 `external_change` 并跳过，不覆盖外部修改，也不声称一定由人工修改。用户随后明确重新授权该项时才能按新原值重新登记。

使用宿主支持的条件更新/事务（若有）；没有时缩小为逐项可撤销操作，紧邻写入重读并记录局限，不把它称为原子保障。若仍无法安全排除竞争则暂缓。仅通过原生标题入口写入，不用内部数据库、历史文件、工作目录或假产物绕过。

原生写入返回成功后，还要读回新标题、原会话 ID 以及历史可读范围；核验通过才标记 `done`。超时、定位失败或结果未知时保留 `pending` / 待核对记录，下次先查实际结果，不盲目重复提交。若实际标题已经等于本次拟议值，也需结合写入回执和历史读回确认；未能证实来自本次写入则保留外部变更，不猜测所有权。

恢复只对用户明确授权、当前仍保持本次新标题的条目，用原生入口恢复原标题；外部后续修改不覆盖。无法核验附件或完整历史时如实写清范围，不能声称零丢失。

## 最小队列与结果记录

这是记录约定，不是可执行 API 或授权凭据。可以沿用宿主/项目已有格式，保留以下意义即可：

| 字段 | 意义 |
| --- | --- |
| context | 应用/版本、设备、账户或工作区；不同环境重新核验 |
| authorizationRef、fixedScopeIds | 真实用户消息引用与本批稳定会话 ID 集合 |
| includesFutureNewThreads | 固定为 false，除非用户另授持续策略 |
| id、originalTitle、expectedOriginalTitle | 对象、可恢复原值和外部变化比较值 |
| anchorUserWorkTurnId、isCallingThread | 当前聊天例外的业务完成锚点，普通候选不适用 |
| evidenceTurnIds、contentBasis、proposedTitle | 当前实际内容依据和拟议标题，非完整聊天 |
| status、lastCheckResult、writeAttempt、readback | pending / done / external_change；等待、失败、未验证、已准确保留等具体结果和检查点 |
| followupId、followupStatus | 真实专用跟进标识与配置/实际触发/停止的核验状态 |

已经准确无需改名的项以 `done` 加 `accurate_unchanged` 记录；外部修改跳过项以 `external_change` 终结。失败或没有可靠读回的项不终结。报告分别统计真正更名并验证、准确保留、外部变更跳过、等待和失败，不把检查过数量当成功改名数量。

有统一进度要求时，开始前登记同一个稳定任务 ID，执行时同步实际核对/写入/读回量。心跳只覆盖实际维护执行；等待业务结束时立即切为等待/暂停，停止旧速度和 ETA。回读 API 和实际页面核对状态；任务结束关闭页面不会取消已配置的原生跟进。进度服务不负责启动或判断其他聊天业务。

`scripts/upkeep_guard.py` 仍只用于持续策略的离线合同，不能验证本流程的真实授权或执行队列。不要为通过离线守卫伪造标题所有权、活动状态或改写其保护字段。
