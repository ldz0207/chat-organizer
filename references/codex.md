# Codex 分支（仅目标为 Codex 时加载）

确认桌面、CLI、IDE 扩展或其他形态及当前版本。以当前可用工具、内置帮助和官方文档核实任务/会话组织能力。项目组织、仓库列表和任意历史会话分组不自动等价；产品名匹配也不代表所有界面能力相同。

只使用当前公开接口/原生 UI 明确支持的动作。不能从其他产品推导 Codex 数据位置、数据库 schema 或写入语句；不读写受限会话目录。没有受支持历史归组动作时，只生成分类提案/导出映射，说明尚未改变侧边栏。

此分支不依赖、不加载、不执行 WorkBuddy 资料或 selfheal。用户另行明确要求整理 WorkBuddy 时，先确认目标应用/设备，之后才切换匹配分支；不能因为本机有其他应用数据而自动切换。

## 项目与分组：简单理解

项目决定关联哪些工作目录；分组决定对话放在哪里好找。对已有对话执行原生归组，保持实际项目与工作目录；一个组可以有不同项目，同一项目的对话也可以分在不同组。适用指引按实际项目/目录与已注入规则判断，组名不决定指引。

从分组内新建是另一操作，应用可能预选关联项目；发送前核对实际项目与目录。放在同组不会自动共享全部聊天正文，也不表示项目文件已全量读入上下文。当前形态不支持纯侧边栏归组时只给建议。

项目目录依据：[官方项目与对话说明](https://learn.chatgpt.com/docs/projects)。分组行为以当前原生接口和实际读回为准。

## 按内容命名的原生路线

用户明确授权随当前聊天实时命名与归组时，使用 [当前回合收尾](turn-upkeep.md)。当前 Agent 可在最终回复前处理自己的活动会话；普通候选的空闲要求及下文固定结束队列保持。现有 `UserPromptSubmit` 可给当前回合添加该收尾指引，但不直接执行语义分类；不要把它写成已投递的结束事件。

用户单独授权“旧会话继续聊天后自动到原组顶部”时，转入[Codex活动排序](codex-recency.md)。这是现有归属内的视觉位置调整，可处理当前活跃会话，不改变项目、工作目录或运行状态；分类与改名仍按下面的保护边界执行。


仅在当前 Codex 暴露相应工具时使用：`list_threads` 盘点范围，`read_thread` 读取实际轮次，`set_thread_title` 按稳定会话 ID 逐项串行改名。列表摘要不能代替实际用户请求和最终交付。接口名称、字段和状态含义以当次工具元数据为准；CLI/其他形态没有这些接口时只给建议，不读取内部数据库或受限会话目录。

核对返回的 `kind`、`hostId`、会话 ID 和应用版本，防止跨主机、ChatGPT 或云端对象混入。若工具允许省略 `hostId` 自动定位，可读取后核对返回主机；显式主机查询失败时也只能通过受支持接口复核，定位仍不可靠则等待，不据旧缓存写入。

普通候选必须为 `idle` / `notLoaded`，且读取范围内无 `inProgress` 业务轮次；其他状态不自行解释成已结束。当前聊天仅标题维护回合的例外须按 [会话内容命名](content-titles.md) 核对原用户工作锚点，不能用当前维护活动替代业务完成证据。

用户授权“本批运行结束后命名”后，可用当次受支持的原生 `automation_update` heartbeat 跟进固定队列。优先结束事件；没有可用事件时用适度检查间隔并安静等待。先核验确实已配置，实际触发后再记录已执行。全部条目终结后只暂停本次专用跟进并读回；共享自动化只移除本批工作，保留其他已授权工作。暂停前保留现行配置，更新时不覆盖其他字段或用户修改。不能通过给其他聊天发送消息来催停或推进业务。

## 明确请求归档时

用户另外要求清理已完成或长期不用的桌面会话时，转入 [会话归档审阅](codex-archive-review.md)。当前安装的工具必须真实暴露 `set_thread_archived`、`list_archived_threads` 和内容读取能力，才执行原生归档。核对当前工具参数、主机与返回对象，不能把 ChatGPT 对话、其他设备、项目或工作树当作同一归档对象。其他形态或缺少可核验逆操作时只给预览。
