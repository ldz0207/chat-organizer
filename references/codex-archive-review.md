# Codex 桌面会话归档审阅

仅在用户明确要求清理、减少侧栏会话或归档旧会话时加载。安装技能、分类、改名及组内活动排序授权均不包含归档。保留现有组名、组 ID、人工归属、标题、项目与工作目录；不新增归档组。使用原生归档状态隐藏条目，不能以删除会话、移除项目或归档工作树代替。

## 盘点完整范围

先核验当前应用、设备、账号范围、读取与归档/取消归档能力。以当次工具元数据为准；某个桌面版本可用不代表 CLI、IDE、云端或其他版本同样可用。

`list_threads` 可同时含 Codex、ChatGPT、远程主机和置顶条目，且最近列表可能有数量上限。必须核对 `kind`、`hostId`、分页和覆盖范围。当前受支持的原生元数据查询能够补齐本机历史时，使用其分页和供应商筛选参数，追踪游标直至结束并按稳定 ID 去重；不能因为一次返回未满请求数量，就声称没有下一页。独立元数据连接中的 `notLoaded` 只说明该连接没有加载业务，不能证明桌面没有运行任务。

元数据仅保留分类必需的 ID、原标题、原归属、活动时间、保护标记和状态。全量盘点不等于全量导出正文。对候选用 `read_thread` 读最近实际用户请求和最终答复；末轮空白、仅“收到”或被中断时，有界补读前一两轮。读取工具不能按字段可靠限长时，提取必要证据后再保存/展示，不整批存储原文。仍不足以判断时列为不确定，不补扫所有历史。

活动时间只用于决定审阅顺序。近期完成的一次性任务也可归档，旧任务也可能仍有重要未决项。保留置顶、当前聊天、运行或排队任务、固定协作入口、后台自动化及仍在使用的科研入口；对默认保护对象仅提出另行确认建议。

## 根据实际结果分类

| 类别 | 需要的证据 | 提案中的表述 |
| --- | --- | --- |
| 已确认解决 | 最新请求对应的修改与验收，或明确的用户确认 | 具体说明修复了什么、验收范围 |
| 交付完成 | 一次性答复、文件、安装、配置或核验已经按请求交付 | 标注交付结果及有限验证，不把未验证效果写成已解决 |
| 待办已移交 | 用户明确暂缓，且 Issue、项目状态或既有待办实际存在并可读回 | 给出待办入口，未来工作仍未完成 |
| 后续结果覆盖 | 后续会话或持久记录实际覆盖了原请求与独有未决项 | 指明覆盖证据，保留当前续接入口 |
| 长期搁置 | 无运行任务，但最后停在确认、认证、反馈、未修复或中断 | 单列未完成事项；仅在用户明确批准该类/具体清单后归档 |
| 保留或不确定 | 当前使用、重要未决项或证据不足 | 说明保留理由，不根据完成状态猜测业务结束 |

`completed` 只表示模型回合结束。它可能包含失败、拒绝、待确认或未修复的结论，不能作为解决证明。标题也可能与后来的主题不同，按最新真实内容判断；本次归档不顺带改名。

展示完整候选清单：稳定 ID、当前原题、最后活动日期、原组、类别、理由、未决项、实际覆盖范围与保护对象数量。正文可汇总，逐项清单留用户可打开的私有文件。区分“已完成”和“搁置”，不为达到归档数量把未解决对象混入完成类。

用户要求先确认时，等待具体批次确认；批准已有清单后可执行该批并继续扩大只读筛选，不能把“再多找一些”当作对尚未展示条目的无限归档授权。不重复询问已明确批准的同一批次。本流程默认一次性，不增加自动归档规则、heartbeat 或后台执行器。

## 让用户快速批量选择

用户仍关注部分候选时，不再仅提供“整批归档/全部保留”。优先提供可勾选的审阅清单，按实际最新内容整理主题，而非仅按原标题分类；每条显示原题、简短内容与结果、最后活动和未决事项。明显不准确的原标题保留，旁边说明实际内容。

- 初始全部不选。未勾选表示保留，不把推荐或预选视为批准。
- 支持主题/完成类别筛选、批量选中当前筛选结果、逐项取消，以及“关注保留”标记；批量操作跳过关注项。筛选不会清空其他页面的选择。
- 显示所选总数、搁置未完成的所选数量及预计剩余数量。批量选择仍保留逐项理由与稳定ID映射，不能把“搁置”改标成“解决”。
- 用户提交选择时生成包含清单版本/摘要和所选稳定ID的明确指令。交互状态保存、勾选和复制都不算实际归档授权；需用户明确发送/确认该指令，执行前再次核验当前状态。
- 没有交互能力时提供同样编号的短表，接受“归档这些编号，其他保留”或逐项选择。界面和真实资料仅在私有任务范围生成，不写入公开方法仓库；不新增常驻服务。

## 原生执行与读回

1. 执行前用当前原生列表和内容读取再次核对主机、稳定 ID、标题、原组、最近轮次与业务状态。新消息、改名、归属或保护标记变化时暂缓受影响项；没有跨客户端原子事务时如实说明这一限制。已有排序/分类维护同时写侧栏时，协调该批写入并保留原批准策略；归档造成成员变化而触发守卫时，先核验变化再恢复，不能清除用户暂停或跳过能力/权限失败。
2. 将原值映射、批准批次及恢复入口写到用户控制位置。不能保存恢复记录时停止写入。按当前暴露的 `set_thread_archived` 参数显式选择目标主机和归档状态，逐条串行执行；不得通过内部数据库、会话文件或全局状态写入。
3. 每次成功保存工具回执。超时或结果不明先检查原生现状，不盲目重试。当前聊天、运行任务和置顶对象不得通过停止任务或取消置顶来绕开保护。
4. 用 `list_archived_threads` 分页核对归档 ID；独立读取未归档范围确认这些 ID 已退出，再用 `read_thread` 核对原 ID、原题、工作目录和历史仍可访问。比较组名/组 ID、保护对象、失败与跳过清单。数量变化需考虑其他聊天并发创建或归档，不能只靠总数判断成功。
5. 用户要求恢复时，按当前工具核验取消归档参数并串行恢复，读取列表与历史。应用是否自动恢复原组/位置须实际读回；不足时只恢复本批原归属，保护后来人工更改。支持逆操作不等于已经做过恢复实测。

只报告成功、失败、跳过、待确认与未验证范围。不声称归档清理了项目文件、自动缩小其他会话上下文或停止模型消耗。内容审阅使用当前 Agent 的模型 token；原生写入不另起业务模型回合，本流程没有新增常驻内存或定时审阅成本。

## 方法与个人证据分开保存

通用流程及合成示例可在用户授权的来源仓库中更新。真实会话 ID、原标题、分组映射、正文摘录、授权与恢复回执保存在本机/NAS的私有记录，不上传公开仓库。PR 说明写问题、方法变化与实际验收范围，不引用私人清单；未经明确授权不合并。
