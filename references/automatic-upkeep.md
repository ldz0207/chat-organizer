# 可选自动标题与增量维护

本页用于持续维护策略。用户只要求本批按实际内容命名、运行结束后补命名时，改读 [会话内容命名](content-titles.md)：明确的本批改名授权可以覆盖指定的已有标题，不能套用持续策略的默认标题所有权判定而拒绝执行；登记后的外部变更仍受保护。

## 默认关闭，一次确认精确范围
首次先确认分类的组名、数量与规则，再让用户选择：仅建议 / 自动归入已批准组 / 自动标题 / 两者。初始整理与未来维护可同一次确认，但必须分清一次性任务与持续策略。

持续策略必须绑定目标应用、账户、设备/工作区、版本证据、固定分类摘要；记录允许任务类别（默认新建/未分组且空闲）、允许动作、标题风格与长度、真实触发机制、每批/每小时上限、防抖间隔、有效期或明确持续到暂停、异常报告与撤销方法。保存真实用户答复/消息引用。策略文件不是授权来源；代理须核实用户确实批准且未撤销。

授权内后续归组/标题更新不用反复问。新增/改名/删除/合并组、改变规则或风格、移动已归组任务、扩大账户/设备、增加权限/插件信任/访问范围等，先给差异再确认。应用版本变化先暂停自动写，重新核实能力并确认更新后的策略上下文再恢复，不能复用旧缓存。停止/撤销自动维护时停止后续动作，不自动删数据或恢复旧标题。

## 持续自动标题

有一种独立的、需明确授权的 [当前回合收尾模式](turn-upkeep.md)：用户可预先授权当前 Agent 接管策略启用后新建会话的初始标题，不必伪造宿主的 default/policy 所有权标记。必须记录授权、首次原值和原生读回；手动锁及登记后外部变化仍受保护。没有这种明确的前瞻授权时继续执行以下默认所有权合同。此例外不扩展到旧会话未知来源的标题，也不放宽对其他运行中会话的保护。

- 仅宿主原生支持读回和改标题、可安全验证所有权与并发时开启。组名与标题是两种功能，hook 存在不代表具备改标题 API
- 初始候选必须由宿主证明为默认/未命名标题；或当前标题与已记录的**最后一次由本策略写入且读回成功的标题**完全相同。手动标志、手动锁、当前标题不同、来源未知时都跳过，不猜“看起来像默认”
- 用户任何手动修改都会使该任务退出自动标题管理；保守记录 external-change / ownership-lost（不声称一定由人工修改）并锁定，除非用户单独明确解除并指定恢复范围。若用户把标题改回旧值且宿主不提供来源证据，不能只靠字符串相等认定无人工编辑，应暂停
- 风格示例可提“简短动作 + 核心对象，20字以内，不加日期/emoji/分组前缀”；这是待用户选择的示例，不是强制规范。不从私密摘要添加敏感信息到更显眼的侧边栏
- 仅在主题稳定、任务空闲、用户输入已完成时提出标题；避免每次 token/工具调用刷新。无足够信息时保留原名，多主题/信息冲突只给建议
- 提交前重读 title、ownership、revision、活动状态；使用受支持条件写入。无可靠条件写且可能并发人工编辑时不自动写。成功读回后才更新管理指纹与审计；失败不能标记已管理

## 触发与退化
优先当前宿主**真实、已核实、用户已信任/启用**的事件机制。登记实际官方事件名、发生阶段、payload、权限和执行上下文；本包不预装 hooks，不假设通用事件名。检查多来源重复注册，避免同一 hook 安装两份；无稳定事件/回合标识时不猜去重键，转为调用时单次评估。事件仅唤起维护评估，所有数据、权限与状态仍需重新读取。

把密集事件合并为一次评估，待任务空闲和防抖窗口结束；限每次与滚动时间窗动作数。重复事件/已完成目标为 no-op，结果未知先查询。单实例租约/锁与原生条件更新都要考虑；本地锁不约束其他客户端。

如果宿主只有 prompt/turn 入口，在技能被调用或可用的宿主机会点评估已有策略；没有真正事件投递就不会自行唤醒，不承诺全天后台工作。无可用 hook/执行能力时保留建议，必要时说明可采用的真实替代方式，不能偷偷创建每周定时任务或伪造守护进程。

## 复用已有维护入口

用户已经明确授权随既有周维护、备份或其他入口调用时，复用该入口与持续授权范围；仅加入一次本技能调用，保留原任务的时间、状态与其他内容，不因技能接入启动备份或恢复暂停任务。该方式不要求再建立一个专门的每周整理任务。没有真实触发入口时只记录方案与缺口，不声称自动运行。

## 审计与安静维护
用户明确要求Codex现有自定义组按聊天活动持续上移时，使用独立的[活动排序适配器](codex-recency.md)，核实本机原生元数据与侧栏读回后显式启动。它仅改变同组位置，可在聊天运行时处理；不扩大这里的自动分类/标题合同，不安装hook或新周期Agent任务。真实worker与仅机会式调用的维护须分别记录。

维护最小审计：策略版本/hash、上下文范围、触发类型、稳定任务 ID、动作指纹、前/后值、revision、结果与时间。事件去重优先存哈希和计数，不存 prompt/transcript 原文；去重哈希不能冒充原生任务 ID；标题也是私人数据，留在用户控制位置。失败/未知/回退分开记录，未解决失败持续暂停后续写入，不能等限频窗口过期就自行恢复，不将 dry-run 记为成功。

常规成功不每条打扰，可提供可查摘要；需要决定、人工锁冲突、权限失效、超范围或验证失败时集中提示。触发风暴进入冷却，达到限额的任务只延后，不丢弃；下一次真实事件/调用继续评估，不能假定离线脚本会定时重试。

用户审阅可接受、修改、单项锁定或跳过；这些是对话/原生应用操作选择，不把HTML勾选框或JSON字段当授权。

## 本包离线辅助
`scripts/upkeep_guard.py` 读取合成/导出候选与声明策略，只判定 covered_by_declared_policy / pending_approval / deferred / skipped；不验证真实同意、不创建 hook、不执行动作。可用 `--html` 输出无脚本、已转义的人类审阅报告。任何 covered 状态仍要由真实 Agent 验证授权、能力、并发和备份。

该脚本只评估其既有持续策略合同，不处理本批内容命名队列、专用结束后跟进或当前聊天维护收尾例外。不要伪造 default/policy 所有权或空闲状态来让本批改名通过它。
