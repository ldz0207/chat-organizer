# 当前回合收尾命名与归组

用于用户明确要求新会话在首轮回复或主题清楚时整理，后续继续聊天出现主要主题变化再更新。由正在答复的 Agent 在最终回复前完成；这是当前回合中的工具操作，不是回复后另起一轮模型任务。本包只提供方法，不自动部署宿主入口或授权。

## 入口与范围

核实宿主、调用会话 ID、设备/账户、当前原生工具和持续授权。复用已信任且真实投递的规则/回合入口，把收尾要求加入当前 Agent 的上下文。只有安装文件、配置 enabled 或离线运行读取器都不证明未来回合会触发。

Codex 的 `UserPromptSubmit` 可返回 `additionalContext`，提醒当前 Agent 收尾；它发生在用户输入时，不是结束事件。`Stop` 的阻止决定会产生新的模型续跑，不符合不另开模型任务的目标；本模式不安装它。依据：[官方 hooks 文档](https://learn.chatgpt.com/docs/hooks)。

持续策略记录实际用户授权、启用时间、设备/账户、固定已有组 ID/名称/语义、标题风格和允许对象。只处理调用 Agent 自己的普通本机会话；不扫描或修改其他活动聊天，不发送消息、改变项目、工作目录、运行状态或归档。置顶、后台自动化、远程/云端、ChatGPT、明确手动锁均跳过。当前调用会话可以仍为 active/inProgress，这是已授权的有限例外。

## 何时判断

1. 首次用户输入已足够说明主要目标时，在首个最终回复前完成一次命名/归组。笼统“你好”“测试”或信息冲突时延期，后续真实用户消息再判断，不新增唤醒。
2. 后续沿用当前聊天已读请求、关键交付和实质主题变化。标题准确或只多了一项细节时不写；主要目标变化才重新拟名，通常简短动作加对象，20至35字以内，不加日期、emoji或分组前缀。
3. 已有人工归属保持。只把未分组的调用会话归入已批准组；已归组项继续使用原组的活动排序，不因标题变化跨组。多主题或不能可靠选择组时保持未分组，下一次真实输入再判断。
4. 同一宿主回合 ID 最多提交一次标题更新和一次初始归组；工具/子任务/进度事件不触发重入。没有稳定回合 ID 时只在本次答复收尾评估一次。

## 原值与人工修改保护

只保存小型私有记录：稳定会话/回合 ID、首次原标题/原组、最后成功读回的标题/组、待核对动作、锁状态与简短内容依据。不保存完整聊天、提示词或附件，不把私有记录提交公共仓库。逐会话文件可避免其他聊天同时更新同一个总表。

用户可明确前瞻授权接管策略启用后新建会话的初始标题。这是初始接管的授权依据，不是宿主已证明默认标题；首次读取原值、核对创建时间与当前上下文后登记。旧会话未知来源标题不得套用该例外；已有标题策略成功记录、原生默认/未命名证据或另有确切改名授权时才处理。

写前重新原生读取当前标题、归属、置顶与身份。标题不同于登记的预期原值/最后成功值，或归属发生外部改变，记录 external_change/ownership_lost 并保持外部值；用户明确恢复该项前不重新接管。已知手动锁优先，用户明确要求保留标题或分组时即时登记。不能识别来源的改动不声称一定是人工操作，不能发现未观察到的改回旧值。

## 写入、读回与现有排序

准备本次原值/拟议值和待写检查点后，紧邻原生写入再次读取。按当前工具参数通过 `set_thread_title` 和 `move_thread_to_sidebar_section` 等已验证原生入口逐项执行，再读回同一 ID 的标题、原组/目标组及项目/cwd。无可靠条件写时说明这是紧邻复读和可撤销逐项操作，不宣称宿主事务或完全消除人工竞争。

只有原生读回一致才更新最后成功值和回合去重记录。超时或结果不明先核对，无法确认则暂停受影响动作，不盲目重发。失败的标题操作不阻断原用户业务答复；必要时短报维护错误。

初始归组仅新增该调用会话，保持原有组名/ID、成员和其他成员相对顺序。与活动排序写入冲突时暂停受影响动作并核对，不放宽排序的成员/身份守卫。沿用其下一次真实活动处理组内位置，不另做全组静态重排。

## 验收与资源说明

分别记录入口配置、实际指引投递、首次新会话标题写入、首次归组读回、主题变化更新和外部编辑保护；未发生的自然场景保持待验。不创建测试聊天冒充用户新会话，不为验收打断其他聊天。

语义判断会使用当前模型回合的少量上下文与工具 token；不宣称零 token。复用当前 Agent 已有内容，不另外调用模型 API、不增加常驻进程或日程。仅安装技能的其他设备需要接入实际入口并核验其授权，不能直接复用本机 ID/配置。
