# 来源与迁移说明 · 2.2.0

## 来源与版本
本包从既有 WorkBuddy 专用任务整理方案的保护目标演进，独立重写为宿主感知流程；不包含其私有数据库/历史文件写入代码。公开项目的设计灵感和链接见 [设计参考](inspiration.md)，未复制未经许可的社区源码。

2.0.0 建立轻量入口、按需宿主分支、先确认分类和纯离线预览；2.1.0 增加可选自动标题与有界持续维护；2.2.0 增加按实际内容命名及本批业务结束后补命名。版本号描述本包演进，不证明任何目标应用版本已兼容。分类采用语义明确前提下尽量少的原则；不同设备和目标应用分别核验。

## 保留并强化
| 原包意图 | 新版处理 |
|---|---|
| 先摸底、再与用户确认分类 | 首次确认组名、总数、规则及具体映射；可选有界持续授权，授权内增量动作不反复确认 |
| 不绑定个人用户名和路径 | 不设统一数据/安装目录，设备/账户重新识别，便携规则与本机 ID 分开 |
| 保护手动标题 | 默认保留；持续自动管理须证实所有权；用户明确授权的本批改名另走内容流程，登记后外部变更仍保护，离线工具不执行写入 |
| 跳过运行任务 | 加入当前活跃、未知、归档、删除、后台自动化及专有项目保护 |
| 后续沿用业务分类 | 默认增量预览，保留已有组/顺序，规则变更仍可经用户确认 |
| 备份、幂等与自检 | 写前一致性、恢复覆盖面、逐项逆操作、并发条件、失败日志和原生读回 |
| 防止 JSONL 转义破坏 | 不修改历史文件；保留为独立修复研发的完整性要求 |

## 明确替换或停用
- 原版假定 WorkBuddy 私有字段/目录语义可普遍适用。新版以版本与实际原生能力为准，不移植写库语句到 Codex 或通用运行器
- 原版 `--apply` 自动调用 selfheal。新版完全拆开分组与诊断/修复；未获单独批准绝不自愈
- 原 init 的 locked 标记主要控制文案/锁定状态，未严格阻止新增目录；新版不把布尔标记当批准或安全边界
- 原 init 调用 selfheal 后没有以返回码阻止“配置锁定/成功”收尾；新版部分失败与结果未知必须明确记录，不能宣称完整成功
- 原 selfheal 用最大副本选来源、反解连字符目录推 cwd，并对备份错误有忽略路径；新版不保留这些可写行为。路径编码可能歧义，备份失败必须停止
- 原 dry-run 不覆盖全部真实修复分支；“计数为零”不证明无风险。新版明确区分离线校验、原生预览与实际操作验证
- 不自动改 cwd、改任务类型、建假产物使空间显现、重启应用、覆盖历史或给任务加前缀

## 如何替换旧包
本交付只生成文件，没有安装。由用户按目标宿主的受支持技能管理方式选择新包；若旧版同时启用，先检查触发冲突，并经用户同意停用旧技能。不要把新版脚本覆盖到旧目录后继续运行原 `--apply`。

旧 grouping-config.json 不直接当新版输入或批准；可只读提取分类名称与含义作为建议，去掉旧绝对路径/设备 ID，重新盘点当前宿主、解释能力差异并确认方案。旧备份与旧原包保留在用户原位置，本包不删除、不迁移它们。

## 2.1.0 相对 2.0.0
- 取消“任何未来批次都重复确认”的刚性限制；默认仍预览，用户可一次明确批准固定分类及标题风格下的有界持续策略
- 新增独立编写的自动维护守卫、合成示例、静态 HTML 审阅和测试；仅离线判定，不是假后台服务
- 吸收已核实公开项目的轻量触发、最小事件记录、人工标题保护、冲突使计划失效、按项回退等思路，不复制未获许可的代码/文字
- 不吸收容量逐出、自动重排已有任务、固定产品私有写库、强制冗长标题或每周重复手工整理
- 包的交付不等于启用设备上的 hook、自动策略、原生权限或后台任务

## 2.2.0 相对 2.1.0
- 用户要求按内容分类或命名时，读取真实请求、交付及后续主题，不能只读标题或摘要
- 明确的本批改名请求可直接执行其范围；保留准确标题，不扩大到未来新会话或其他设备
- 待业务结束的固定队列保留原值、内容证据和读回结果，外部修改跳过，失败或未知结果继续待核对
- 当前聊天维护收尾例外只适用于已完成的原用户工作；不放宽其他运行中业务的保护
- 原生跟进的配置、实际触发、等待和停止分别核验；维护等待不保持虚假心跳或旧 ETA
- 新增流程为 Agent 指令，现有离线脚本输入合同不变，也不增加通用改名执行器或伪守护进程
